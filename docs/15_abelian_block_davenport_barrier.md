# Zero-sum barrier for abelian-block compression of width-five PBPs

Checkpoint 2026-10-29. Elementary deduction using a standard Davenport-constant upper bound, NOT a lower bound on general SAT algorithms.

## Setting

Normalize a width-five permutation program into W(x)=prod_{t=1}^T h_t^{x_{i_t}} A, with h_t∈S5 and A fixed. Partition the normalized word into r consecutive abelian blocks. Let H_j≤S5 be the abelian subgroup generated by the j-th block. For each variable i define a_i=(a_{i,1},...,a_{i,r})∈K=prod_j H_j, with a_{i,j} the product of occurrences of that variable in block j. Then W(x) is determined by the product-sum Φ(x)=prod_i a_i^{x_i} in the finite abelian group K. The ordered product g_1...g_r A is obtained from its tuple coordinates.

For S5, |H_j| ≤ 6, hence |K| ≤ 6^r. Moreover every permutation in S5 has order dividing 60, so the exponent e=exp(K) divides 60.

## Proposition: AND requires linearly many blocks

Assume the program accepts precisely the input 1^p (or, after flipping individual input variables, any single specified assignment). Consider the p-element sequence a_1,...,a_p in the abelian group K.

If there were a nonempty subset I⊆[p] with prod_{i∈I} a_i=1_K, then Φ(1^p)=Φ(1^p with coordinates I set to 0). The outputs of the program for these two distinct inputs would coincide, contradicting recognition of the singleton. Therefore the sequence (a_i) has **no nonempty zero-sum subsequence**.

By definition of the Davenport constant, p ≤ D(K)-1. The classical van Emde Boas–Kruyswijk/Meshulam upper bound is

    D(K) ≤ e (1 + ln(|K|/e)) ≤ 60 (1 + r ln 6).

Consequently

    r ≥ (p - 59)/(60 ln 6).

In particular r=Omega(p), independently of the original word length T, for EVERY normalized width-five permutation program recognizing AND_p and EVERY representation of it as a product of r consecutive abelian blocks.

Note: numerical constant is far from optimal; only the linear qualitative statement matters.

This does NOT imply general PBP-SAT takes exponential time: AND_p-SAT is trivial. It merely proves that trying to show all polynomial-length width-five programs have r=o(p) is impossible. Any universal algorithm must exploit additional structure even when the word has linearly many noncommuting blocks.

## Why this matters for research

The abelian-block algorithm in docs/14 solves SAT in O(T+(p+r)6^r), so r=o(p) yields subexponential time. The above proposition shows this criterion cannot be universal even for the simple AND function, not to mention Barrington-hard NC1 functions.

Possible next steps:
1. Identify cancellation/annihilation phenomena in nested commutator words that bypass worst-case block count.
2. Find an input-efficient symbolic representation of sets of attainable group products more compressed than arbitrary subset-sum DP on K.
3. Exploit the exact Barrington syntactic commutator tree when supplied, rather than the fully expanded permutation word.
4. Separate solvable- and nonsolvable-generated subgroups, using finite-group ProgramSat results.
